# Qwen3.5-Plus 解析器差异离线核查

## 结论与范围
针对 Figure 1 所用的实验一，未发现本地请求组织、重试合并、响应配对、解析实现或统计计算错误。全量核查 1,152 条已记录响应；没有新增 API 调用，没有替换论文、原始数据或既有结果。这是代码与原始记录的离线交叉核查，不是新增模型实验或人工独立验证。

## 为什么差异大
错误更正条件下，每种策略 48 条响应：

| 策略 | 裸 JSON 条数 | 外层围栏条数 | 严格联合正确 | 规范化联合正确 | 围栏内正确、被额外恢复 |
|---|---:|---:|---:|---:|---:|
| 边界策略 | 22 | 26 | 22 | 48 | 26 |
| 证据绑定 | 36 | 12 | 35 | 47 | 12 |

边界策略的 26 条 fenced 响应内容都正确；证据绑定的 12 条 fenced 响应内容也都正确。证据绑定剩余的一条数值错误来自裸 JSON，而非围栏恢复。两种解析器使用同一个原始 content；规范化仅剥离整段响应最外层的一对围栏，没有修正文中数值或接收者。

严格下 (35−22)/48 = 27.0833%（+27.1 pp）；规范化下 (47−48)/48 = −2.0833%（−2.1 pp）。交互为 [(26−12)/48] × 100 pp ≈ 29.2 pp。这里是点估计变号；规范化的 95% 配对任务 bootstrap 区间 [-6.2, 0.0] pp 包含零。

## 运行问题排查
- 预期的 1,152 个 job 全部存在且唯一；服务端响应 ID 唯一。两模型各 576 条，每条件格 48 条。
- 1,204 条 HTTP 尝试的请求哈希均与冻结任务和当前生成函数重建值一致。
- 1,152 条成功尝试与原始响应档案逐对象一致。其余 52 条均为 HTTP 429；错误尝试未进入成功响应分母。
- 本图 Qwen3.5-Plus 错误更正条件的 144 个任务运行（含三种策略）均没有记录到此前失败尝试。边界与证据绑定共 96 条，全部 finish_reason=stop，分别输出 55–61、55–66 tokens，远低于 max_tokens=160。
- 实验一有 1 条 finish_reason=tool_calls，位于仅任务/工作流借口条件，两解析器下均记失败，不属于本图比较，也未从分母剔除。
- 独立的逐行围栏识别与 JSONDecoder 解析实现，在全部原始输出上与现有实现一致；逐条指标与 trial_scores.csv 一致，汇总计数与 condition_counts.csv 一致。
- 依据任务 ID 显式配对重新计算 task-level 和 8-context 敏感性区间，与 paired_contrasts.csv 一致。
- 重新根据记录字段计算任务真值，与冻结案例中的数值和证据 ID 一致。

## 两次重复分别看
| 重复 | 边界：严格→规范化 | 证据绑定：严格→规范化 |
|---|---:|---:|
| 0 | 10/24 → 24/24 | 17/24 → 23/24 |
| 1 | 12/24 → 24/24 | 18/24 → 24/24 |
两次重复均有同方向的不均衡恢复，非由一次异常请求单独造成。两次仍共享相同任务，不是两个独立外部复现。

## 生成设置与解释边界
请求系统提示本来就要求仅输出 JSON、不要 Markdown。temperature=0.2，max_tokens=160，Qwen3.5 使用 enable_thinking=false；未设置 response_format 或硬性约束解码。因此研究测的是普通文本生成接口对格式指令的遵从性，非强制 JSON 模式。

全实验中 Qwen3.5-Plus 有 283/576 条响应可由移除围栏恢复格式，Qwen-Plus 为 0/576。无攻击时也出现大量围栏：Qwen3.5 的边界与证据绑定各有 35/48 条。这说明该现象并非仅出现在某个攻击样本，也不意味着更长提示总会减少围栏。

现有记录支持“这一端点在这些请求设置下频繁输出围栏”；模型后训练习惯、提示结构和服务端处理各自的贡献仍未识别。返回 model 字段均匹配请求的日期标识，但 system_fingerprint 全部为空，故不据此保证服务端权重与内部处理从未变化。后续若要解释成因，应单独冻结新方案，增加格式强调/结构化输出控制或独立端点验证，而不是替换当前数据。
